# Hosted deployment preparation (Render native Node.js)

ExecuBrief includes a Render Blueprint (`render.yaml`) for a native Node.js web service. It is preparation only: no service has been created and no billing has been enabled.

## Configuration

- Node.js: project `.node-version` selects `24.21.0`.
- Build: `npm ci`; start: `npm start`; health check: `/health`.
- The app binds to `0.0.0.0` for production, using Render's `PORT`.
- `API_AUTH_TOKEN` is generated by the Blueprint and is server-side only; production startup refuses to run without it.
- Scheduler and automatic email are disabled in hosted configuration. Demo routes always force email off.
- The Blueprint mounts a persistent disk at `/var/data`. It stores private reports, authentication metadata, per-organisation uploaded-data workspaces, the synthetic demo database, and demo reports under separate paths on that mount. The current paths are configured explicitly through `DATABASE_PATH`, `REPORTS_DIR`, `AUTH_DATABASE_PATH`, `CUSTOM_DATA_DIR`, `DEMO_DATABASE_PATH`, and `DEMO_REPORTS_DIR`.
- Puppeteer installs its managed browser during `npm ci`; Linux render behavior must be verified after the first deployment. The Blueprint enables the no-sandbox flag for the isolated hosted environment.

## Before creating the service

1. Publish the reviewed source to the authorized GitHub repository (`abhinavs1703/Automated-Executive-PDF-Reporting-System`) without `.env`, `node_modules`, local SQLite databases, generated PDFs, or logs.
2. Open Render, choose **New → Blueprint**, and connect only that authorized repository. Review the `render.yaml` plan, storage, and generated environment variables before confirming.
3. Render may create a paid service when the Blueprint is applied; do not proceed without explicit budget approval.
4. Once deployed, verify the actual `https://…onrender.com/`, `/health`, analytics, generation, preview, download, private token protection, and persistence across a restart. The generated public hostname is not known until Render creates the service.

## Cost and persistence

Render's current published plan IDs include `1c-2g` (1 CPU, 2 GB RAM) and paid persistent disks. A 2 GB service plan is the safer starting point for Puppeteer than the 512 MB plan, but load and memory should still be measured. The persistent volume is essential because ordinary service filesystem changes can be lost on redeploy/restart; a free instance is not suitable for the dependable, persistent, always-available requirement. See the [official Render pricing](https://render.com/pricing), [compute plans](https://render.com/docs/compute-plans), [persistent disks](https://render.com/docs/disks), [free services](https://render.com/docs/free), and [Blueprint reference](https://render.com/docs/blueprint-spec).

Costs and plan availability may change. At the current review, Render pricing lists a `1c-2g` service at about **US$25/month** and a persistent disk at about **US$0.25/GB/month**. A 1 GB disk therefore gives a rough base estimate of **US$25.25/month**, before usage-based extras/taxes. Verify the provider pricing page again immediately before activating the Blueprint. Do not activate the Blueprint without approving this recurring cost.
